# Steam Prices Polisher — Project Context and Progress

Last updated: 2026-09-10

## Purpose

Steam Prices Polisher is intended to become an interactive tool for examining a
user's Steam wishlist and finding games whose Polish price is cheaper than or
equal to prices in selected foreign storefronts after currency conversion. The
initial comparison uses PLN as the home currency and USD and EUR as alternatives.

The broader product goal is price transparency and fair treatment of Polish
consumers. The comparison must therefore show its assumptions instead of
presenting exchange-rate arithmetic as a complete measure of consumer fairness.

## Current product stage

The repository contains a tested command-line foundation and a local interactive
web app. `serve_web.py` serves the browser assets in `web/` through a WSGI app.
The original `wishlist_page.html` remains an unused empty placeholder. Public
hosting is prepared and documented, but no deployment has been made.

The current program can:

- accept a numeric SteamID64 or supported Steam profile URL;
- optionally resolve a custom `/id/name` URL with a user-provided Steam Web API
  key;
- retrieve a public wishlist through multiple fallback methods;
- fetch Polish, US, and German Steam prices;
- retrieve NBP exchange rates;
- classify comparable games as fair or expensive;
- cache completed regional requests and resume interrupted work;
- distinguish valid missing prices from technical failures; and
- render incremental progress and categorized results in the console.

## Starting point

The project originally consisted of:

- one monolithic Python script;
- an empty HTML file;
- no Git repository;
- no tests or documentation;
- hard-coded PLN, USD, and EUR comparisons;
- sequential Steam calls with a fixed delay;
- broad exception handling that treated failures as missing prices; and
- a source-code field where users were encouraged to paste Steam cookies.

## Current processing flow

1. Initialize separate HTTP clients for NBP and Steam.
2. Open or migrate `.steam-price-polisher/cache.sqlite3`.
3. Load cached exchange rates or retrieve fresh NBP rates.
4. Normalize the supplied Steam identifier.
5. Resolve vanity names when `STEAM_WEB_API_KEY` is available.
6. Retrieve the wishlist and remove duplicate app IDs.
7. For each game, load the PLN price first.
8. Skip foreign requests when no valid PLN price exists.
9. Load cached USD and EUR prices or request missing/expired regions.
10. Convert alternatives to PLN and classify the game.
11. Persist each response and render progress immediately.
12. Report comparison results, valid unavailable outcomes, and technical
    failures separately.

## Configuration and local data

Supported environment variables:

| Variable | Purpose |
|---|---|
| `STEAM_WEB_API_KEY` | Optional user key for resolving `/id/name` profiles |
| `STEAM_COOKIE` | Optional experimental cookie support for private wishlists |
| `STEAM_PRICE_POLISHER_DATA_DIR` | Overrides the local cache directory |

The project does not automatically load `.env` files. `.env.example` documents
the variables but contains no credentials. Local `.env` files, `wishlist.txt`,
and `.steam-price-polisher/` are ignored by Git.

Region defaults are defined in `steam_price_polisher/configuration.py`; `--regions` selects alternatives:

- home: Poland (`pl`) and PLN;
- comparison 1: United States (`us`) and USD;
- comparison 2: Germany (`de`) and EUR.

## Open work

### Interactive application

Implemented locally with region selection, sortable/filterable results, store
links, incremental progress, cached/live indicators, cancellation, and retries.
Remaining: browser QA, live Steam verification, and host-specific deployment.

### Configurable currencies and regions

The validated catalog and CLI selection are implemented for the existing three
storefronts. Future expansion can add supported storefront/currency pairs. Home
currency conversion remains explicitly limited to PLN.

### Private wishlists

Cookie values are no longer stored in source or sent outside Steam, but reliable
private-wishlist authentication is still experimental. The product needs a clear
security model, validation, expiry behavior, and user documentation before this
can be treated as supported.

### Fairness methodology

The final product must explain:

- the effective date and source of exchange rates;
- that displayed US and EU prices may not have identical tax treatment;
- the role of VAT, payment-provider fees, and conversion costs;
- why Germany is used as the EUR storefront proxy; and
- that currency conversion alone is an indicator, not a complete fairness
  judgment.

NBP publication dates are now retained in the rate model and cache. CLI results
include rate provenance and versioned methodology covering the assumptions above.

### Cold-cache performance

Cold-cache Steam requests remain sequential. The next optimization is carefully
bounded concurrency using the existing shared request gate. Concurrency should
be tuned only after a live smoke test confirms actual rate-limit behavior.

### End-to-end confidence

Still needed:

- command-line tests covering complete and partial exit codes;
- a complete live wishlist run and deployment-host smoke test;
- browser interaction and visual tests for the interactive application; and
- performance measurements for cold and warm wishlists.

## Regional discount research (2026-09-10)

Community reports describe Sekiro's April 2022 sale excluding parts of Asia while
Western regions received 50% off. This is evidence against assuming identical
regional offers, not proof of per-currency discount differences on one identical
package. README records the sources and limits. Website methodology now explains
independent regional checks. No retrieval logic changed: discount metadata comes
with each price response, so assuming a common percentage would not reduce
cold-cache requests. Inference from old regional base prices remains disabled.
